# 交互原理演示 · 可读性检查

## 用户反馈
交互图文字过小、英文术语较密集、同时呈现很多文字，造成了阅读负担。之前将工程拓扑改成逐步流程虽然降低了架构复杂度，但每屏仍同时展示所有步骤、步骤摘要、比较、细节和代价。

## 本次修改
- **12/12** 已有教学专题新增中文的一句话中心解释，每张图保留核心技术名词的英文，面向读者的主叙述改为中文。
- 将所有步骤由同时铺开 3–5 个标题/描述，改成**每次展示一个步骤**，其余步骤仅用可点击数字指示。
- 将每个步骤的技术解释放入默认关闭的“查看技术原理与细节”；不需要读完整段才理解当前变化。
- 页面先呈现一个例子、一句结论和旧新方案的简短对照，之后才出现交互步骤；收益、代价与适用范围折叠在更下方。
- 主解释文字在常见桌面和移动端为 18–22px，关键结论 23–31px，核心步骤标题 25–32px，触摸操作按钮至少约 48px 高。
- 所有资料来源、原有文章链接、实验边界、原理细节与图的 permalink 保留；不改变研究事实或自动选题安排。

## 技术验收及限制
脚本通过静态语法检查，12 篇数据字段与已知文章 ID 一一对应。需在 Pages 构建后实测 JS 点击、键盘顺序和移动端实际排版；静态审查不能替代用户阅读理解测试。
