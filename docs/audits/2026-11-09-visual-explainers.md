# 2026-11-09 · 交互架构图改成原理对照

## 发现的问题
原本多个主题共用“全量节点、连线、Tab、空白详情侧栏”的结构。组件看起来像技术部署拓扑，却没有先告诉读者为什么需要这项优化。不同研究的图也采用相似方框语法，缺少具体例子，手机上还常常需要横向滚动。

## 本次实现
- 覆盖目前目录 `docs/_data/studies.yml` 中 **12** 篇文章的全部交互图链接；保留每一条原有 URL。
- 每张图给出独立的现实问题、具体示例、常见做法与文章方案对照、核心变化、可点击流程步骤、主要收益、工程代价、适用范围和一手来源。
- 默认显示文章方案的关键步骤，按钮允许切换对照流程、逐步阅读。流程卡片为可键盘操作的真实 HTML 控件，而不是需要阅读多个 SVG 坐标和箭头的复杂网络图。
- 所有教学内容集中在 `docs/_data/visual_lessons.json`；公共 Layout/CSS/JS 一次维护，后续每次新增研究必须写独立的正确流程内容，而不能把通用节点模板复制过去。
- 特别标注跨论文组合及研究原型范围：例如 RAG 的 Contextual Embedding 与 Late Interaction 是两条可组合技术；Meta Thin Orchestrator 与 Perplexity Shared Workspace 是两家公司案例；DeepSeek Super-agent 的设计目标不等于公开原型全部已实现。
- 不改变原始论文正文、来源或研究结论；Git 历史仍可找到旧版图的实现。

## 质量检查及限制
- 12 个视觉 ID 与稳定 URL 路径逐项对照 studies.yml，无重复，所有步骤每视图在 3–5 之间。
- 核心变化标在方案里的具体步骤，关联资料为一手链接；脚本通过基础语法检查。
- 尚需通过 GitHub Pages Jekyll 构建和真实浏览器验证交互与移动端布局。静态教学图不能替代系统的完整执行/信任边界图，复杂内容保留在正文。
